# 학과 디렉터리 CSV 일괄 수정 (관리자) — 설계

날짜: 2026-06-18 · 상태: 승인됨 · 출처: 클라이언트(대표님) 추가 질문 — "첨부 목록을 직접 디렉터리에 반영(대량 수정)할 방법"

## 목표
관리자가 학과 디렉터리(학과 + 세부전공)의 **텍스트 정보**를 CSV로 **내보내고 / 가져와서 일괄 추가·수정**할 수 있게 한다. 한 건씩 편집하는 기존 `DeptDirectoryAdmin` 흐름을 보완한다.

## 핵심 결정
- **방식**: 관리자 패널 내 **CSV 내보내기 / 가져오기**. 공개 노출 없음 — 전부 `requireAdmin`.
- **적용 의미**: **비파괴 업서트(추가 + 수정만)**. 파일에 없는 기존 행은 그대로 유지. **삭제는 기존 개별 편집기**로만(대량 삭제 위험 차단).
- **매칭(하이브리드)** — 방식 1·2를 한 구현으로 동시 지원:
  - `id` 있는 행 → 그 레코드 **수정**
  - `id` 빈 행 → 자연키로 매칭(학과: `계열+학과명` / 세부전공: `상위학과+전공명`) → 있으면 수정, 없으면 **신규**
- **범위**: 학과 + 세부전공. **이미지·정렬(ord)은 대상 외**(이미지는 개별 편집기 유지, ord는 수정 시 보존·신규 시 0).
- **파일 형식**: CSV(UTF-8). **인코딩 자동 감지**(UTF-8 실패 → EUC-KR/CP949 폴백) + 미리보기에서 한글 깨짐 **육안 확인 후 적용**.
- **안전**: 업로드 즉시 반영 아님. **미리보기(추가 N·수정 M·오류 K) → 확인 → 트랜잭션 일괄 반영**. 오류 행은 그 행만 스킵.
- **빈 칸 = 기존 값 유지**(기존 행 수정 시 비운 칸이 데이터를 지우지 않음). 신규 행은 기본값.
- **의존성 0**: CSV 파서·EUC-KR 디코드(Node 내장 `TextDecoder`)·diff 모두 자체 구현. 외부 패키지 추가 없음.

## CSV 양식 (내보내기 = 가져오기 동일 스키마)

열 순서:
`id, 구분, 상위학과, 계열, 학과명/전공명, 모집여부, 홈페이지, 위치, 전화, BK21참여, BK21사업단명, BK21홈페이지, 해시태그, 소개`

| 열 | 학과 행 | 세부전공 행 | 비고 |
|---|---|---|---|
| id | 수정 시 채움 | 수정 시 채움 | 내보내기 파일엔 자동. 신규는 빈칸. (학과 id ≠ 세부전공 id, `구분`으로 구별) |
| 구분 | `학과` | `세부전공` | 필수 |
| 상위학과 | 빈칸 | 부모 학과명(필수) | 세부전공의 소속 학과 |
| 계열 | 필수(화이트리스트) | 무시(부모 상속) | `인문·사회`/`자연과학`/`공학`/`예술`/`체육`/`의학` |
| 학과명/전공명 | 필수 | 필수 | |
| 모집여부 | Y/N | Y/N | 빈칸→유지(신규는 Y) |
| 홈페이지·위치·전화·소개 | 텍스트 | 텍스트 | 빈칸→유지 |
| BK21참여 | Y/N | Y/N | 빈칸→유지(신규는 N) |
| BK21사업단명·BK21홈페이지 | 텍스트 | 텍스트 | |
| 해시태그 | 쉼표 구분 | 쉼표 구분 | 예) `#a,#b`. 빈칸→유지 |

DB 매핑: `dir_departments`/`dir_majors` 공통 컬럼(`gyeyeol,name,recruit,homepage,hashtags,location,phone,bk21,bk21_name,bk21_url,intro`). 세부전공은 `gyeyeol` 없음 + `dept_id`.

## 백엔드

신규 모듈 `backend/src/directory-import.js` (순수 함수 위주) + `admin.js`에 라우트 3개.

### 라우트 (`/api/admin/directory/...`, `requireAdmin`)
1. `GET /export` → 현재 디렉터리(학과+세부전공)를 위 스키마 CSV로 직렬화, **UTF-8 BOM** 부착, `text/csv` 다운로드. (방식 1 왕복용)
2. `POST /import/preview` → 업로드 본문(CSV 텍스트/base64) 파싱·검증·diff. **쓰기 없음**. 응답:
   ```
   { encoding: 'utf-8'|'euc-kr', garbledWarning: bool,
     summary: { added, updated, skipped },
     rows: [{ line, action:'add'|'update'|'error', kind:'dept'|'major', name, errors:[] }] }
   ```
3. `POST /import/commit` → 동일 CSV 본문 재전송 + `confirm:true`. 서버가 재파싱·재검증 후 **단일 트랜잭션**으로 반영. 응답: `{ added, updated, skipped }`.

### 순수 함수 (단위 테스트 대상)
- `decodeUpload(buffer)` → BOM 제거 → UTF-8 디코드, 치환문자(U+FFFD) 감지 시 `euc-kr` 폴백. `{ text, encoding, garbled }`.
- `parseCsv(text)` → RFC4180 소형 파서(따옴표·이스케이프 따옴표·셀 내 쉼표/개행). `string[][]`.
- `normalizeRow(headerMap, cells)` → 양식 행 → `{ id, kind, parent, fields, errors }`. Y/N·해시태그·계열 정규화·필수값 검증.
- `buildPlan(rows, currentTree)` → 2패스(학과→세부전공) 매칭·diff. id/자연키 해석, 부모 해석(파일 내 신규 학과 포함), 오류 행 분리. `{ ops:[{type,table,id?,parentRef?,body}], summary, rowReports }`.
- `applyPlan(tx, plan)` → 트랜잭션 내 INSERT/UPDATE. **빈 칸 유지** = UPDATE는 제공된 필드만 SET. 기존 `rowParams` 규약 재사용.

### 검증 규칙
- `구분` ∈ {학과, 세부전공}; 계열 화이트리스트(학과 행); 이름 필수.
- 세부전공: `상위학과`가 기존 또는 파일 내 신규 학과로 해석돼야 함. 미해석 → 오류 행(스킵).
- 자연키 매칭 시 동일 키 중복 발견 → 오류 행(모호) 스킵.
- 오류 행은 **개별 스킵**, 정상 행은 적용. DB 오류 발생 시 전체 롤백.

## 프런트엔드 (관리자 UI)

`DeptDirectoryAdmin.jsx`에 일괄 관리 툴바 추가. **구현 시 `frontend-design` 스킬 적용**(메모리 규칙).
- 버튼: `[현재 디렉터리 내보내기]`(GET /export 다운로드) · `[CSV 가져오기]`(파일 선택)
- 가져오기 흐름: 파일 선택 → `/import/preview` → **모달**:
  - 요약(추가 N · 수정 M · 오류 K), 인코딩 표시, **깨짐 경고 시 빨간 배너**
  - 파싱 결과 표(행별 action·이름·오류) — 관리자가 **한글이 정상인지 육안 확인**
  - `[적용]` → `/import/commit` → 성공 시 목록 새로고침 / `[취소]`

## 에러 처리 · 안전장치
- 2단계(미리보기→확인), 트랜잭션, 행별 오류 리포트, 인코딩 깨짐 감지·경고, 비파괴(삭제 없음).
- preview↔commit 사이 데이터 변경 가능성 → 단일 관리자 환경이라 허용(문서화). commit가 재검증하므로 형식 오류는 재차 차단됨.

## 테스트
- **단위**(우선): `decodeUpload`(UTF-8/EUC-KR/BOM/깨짐), `parseCsv`(따옴표·쉼표·개행), `normalizeRow`(Y/N·해시태그·계열·필수), `buildPlan`(id/자연키/신규, 세부전공 부모 해석, 중복·미해석 오류, 빈칸 유지).
- **통합**: dev Postgres 대상 export→edit→preview→commit 왕복 1건.
